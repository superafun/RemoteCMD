# 飞书设置界面重排设计（Feishu settings reorganization）

- 日期：2026-07-22
- 范围：仅前端 `public/index.html` 的设置弹窗；服务端 `server.js` 不改；功能行为不变。

## 背景

设置弹窗里「飞书」相关四项（app_id / app_secret / 接收 ID / 接收类型）目前挤在「通知」分组内，两行排布、无逐字段标签、无说明文字，下拉的 email/chat_id/open_id/user_id 对不懂飞书的人完全看不懂。用户反馈「看不懂、界面乱」，要求重排得有条理。

## 决策

- 方案 A（已选）：飞书从「通知」分组抽出，成为独立分组「飞书通知（任务完成推送）」。
- 说明文字不常驻（手机空间有限），改为每个字段标签旁的 ℹ 信息图标：电脑悬停、手机点按弹出说明；点别处自动收起。
- 仅改界面布局与文案，**不改任何功能逻辑**。

## 新结构

独立分组「飞书通知（任务完成推送）」，内含四个字段，每个字段一行（左中文标签 + 右输入框 + 标签旁 ℹ 图标）：

| 字段 | 标签 | ℹ 说明 |
| --- | --- | --- |
| App ID | App ID | 飞书开放平台创建应用后得到的 app_id。 |
| App Secret | App Secret | 应用密钥，仅服务端使用，用于换取访问令牌。 |
| 接收 ID | 接收 ID | 消息发给谁：邮箱、群 chat_id，或某人 open_id / user_id。 |
| 接收类型 | 接收类型 | 接收 ID 的类型。推荐 chat_id：把机器人加进群即可。 |

分组标题旁也带一个 ℹ，说明整体用途：任务完成时，飞书会向这里配置的账号或群发一条消息通知你。

保留原有「应用」按钮（一次发送四个字段到服务端）。

## 交互

- 桌面：鼠标悬停 ℹ → 显示说明气泡。
- 手机：手指点 ℹ → 显示说明气泡；点气泡外任意处 → 收起。
- 实现：CSS `:hover` + `.open` 类；一小段 JS 在 `click` 时切换 `.open`，并在文档 `click` 时清除所有 `.open`。不使用原生 `title` 属性（移动端有延迟且不可控）。

## 实现要点（仅 index.html）

1. 把飞书四字段的 HTML 从「通知」分组的 `</div>` 块内移出，新建独立分组容器（复用现有 `modal-row` / 标签样式）。
2. 每个字段改为独立 `modal-row`：左侧 `modal-label`（含 ℹ 图标），右侧 `input` / `select`。
3. 新增分组标题行，标题后带 ℹ 图标（说明整体用途）。
4. 新增 CSS：`.info` 圆形图标 + `::after` 气泡（`:hover` / `.open` 显隐）。
5. 新增一小段 JS：点按切换 `.open`、文档点击收起。
6. `applySettingsFeishu()` 逻辑不变（仍一次发送四个字段；接收类型 `onchange` 仍即时应用）。
7. 现有服务端同步/回填逻辑不变（`feishu_app_id` / `feishu_app_secret` / `feishu_receive_id` / `feishu_receive_type` 的 ws 收发与回填保持原样）。

## 测试

- 桌面浏览器：打开设置 → 飞书独立分组可见；悬停每个 ℹ 显示对应中文说明。
- 手机（荣耀，真机）：打开设置 → 点 ℹ 弹出说明，点别处收起；布局不溢出。
- 修改任一字段点「应用」→ 服务端日志出现对应同步；刷新后回填正确。

## 非目标

- 不改默认接收类型（保持 email）。
- 不加「发送测试消息」按钮（本次不做功能性改动）。
- 不改动服务端、不改动完成标记 / BEL / 系统通知等其他设置。
