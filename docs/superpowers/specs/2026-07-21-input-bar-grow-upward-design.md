# 输入条向上扩展设计

日期：2026-07-21
状态：已确认，待实现

## 问题

展开输入条、输入超过一行时，文本框目前**向下**扩展：输入框底边与「发按键 / 换行」按钮的底边不再平齐，文本框整体拉长把整个页面撑得比屏幕还高，导致底部栏（含换行按钮）被挤到屏幕外，需要下滑才能看到全部内容。

根因（`public/styles.css`）：
- `#hotkeys-bar` 与 `#inputBarWrap` 均为 `align-items: flex-start`，输入框变高时左右按钮贴**顶**，文本框向下长。
- `#hotkeys-bar` 处于正常文档流，页面总高超过视口后底部栏掉出屏幕底边。

期望行为：输入超一行时，输入框**向上**扩展、盖住终端底部一部分，而「发按键 / 换行」等按钮的底边始终与屏幕底边平齐、永远可见。

## 方案

纯 CSS 改动（3 处）+ 1 处兜底，不改动 JS 逻辑（`autoGrow` 已按 `scrollHeight` 撑高，上限由 CSS `max-height` 钳制，无需改）。

### 1. `#hotkeys-bar` 吸底

```css
#hotkeys-bar {
    position: sticky;
    bottom: 0;
}
```

- `sticky; bottom:0` 让底部栏底边锁在视口底边；同时保留在 `#page` 正常流盒内，**宽度自动等于终端宽度**（不会像 `fixed` 那样变成全屏宽）。
- `sticky` 只在页面被撑得比视口高时才吸住底边——即输入条展开变高的那一刻才生效；输入条关闭、页面未超高时，栏待在终端下方，行为与现状一致。
- 效果：无论输入框多高，「发按键 / 换行 / 快捷键」始终贴屏幕底可见。

### 2. 输入框改底部对齐（向上长）

```css
#hotkeys-bar { align-items: flex-end; }   /* 原为 flex-start */
#inputBarWrap { align-items: flex-end; }   /* 原为 flex-start */
```

- 原 `flex-start` 让按钮贴顶、文本框向下长；改为 `flex-end` 后，文本框底边与按钮底边平齐，文字越多就**向上**长，盖住终端底部。
- 输入条关闭时所有子项都是单行高度，`flex-end`/`flex-start` 无视觉差异，改常量是安全的。

### 3. 提高上限到约半屏

```css
#inputBarText { max-height: 50vh; }   /* 原为 160px */
```

- 超过半屏后内部滚动（`overflow:auto` 已具备），符合「盖住一部分终端、不盖满」。

### 4. 兜底：安卓键盘不遮挡

根节点（`:root` 或 `html`）加：

```css
:root { interactive-widget: resizes-content; }
```

- 现代 Chrome 默认 `interactive-widget: resizes-visual`，键盘弹起时 `sticky`/`fixed` 锁底元素停在视觉视口（键盘上方），不会被盖。此行为兜底更稳，无需 `visualViewport` JS。
- 注：本项目移动端走 HTTPS 真机测试，按「先桌面实现、真机再调」推进。

### 5. 栏背景不透明

```css
#hotkeys-bar { background: <终端/页面背景色>; }
```

- 吸底后栏会盖住终端，必须给 `#hotkeys-bar` 不透明背景，否则终端文字会透出来。
- 颜色取终端/输入框一致的深色（如 `#1e1e1e`；若终端用了非默认主题色，实现时读取实际背景色对齐）。

## 行为对照

| 场景 | 改前 | 改后 |
|---|---|---|
| 输入条展开、多行 | 文本框向下长，页面被撑高，底部按钮掉出屏幕，需下滑 | 文本框向上长盖终端，按钮始终贴屏幕底 |
| 输入条关闭 | 底部栏在终端下方 | 底部栏仍贴屏幕底（未超高时同现状，在终端下方） |
| 文本超半屏 | 160px 后内部滚 | 50vh 后内部滚 |

## 边界与已知限制

- **短终端场景**：若终端行数很少、页面总高小于视口，`sticky` 不会把栏拉到屏幕底（sticky 只在溢出时吸住），栏仍待在终端下方、屏幕底可能留白——与现状一致，非回归。
- **盖住终端**：展开长文本时栏会遮住终端底部半屏（已确认要半屏），终端可在栏后方正常滚动。
- **安卓**：依赖 `interactive-widget` 默认行为，真机若异常再迭代，不预加 `visualViewport` 逻辑。

## 涉及的现有文件

- `public/styles.css`：`#hotkeys-bar`、`#inputBarWrap`、`#inputBarText` 规则；`:root` 加 `interactive-widget`。
- `public/index.html`：无需改动（`autoGrow`、`toggleInputBar` 等逻辑不变）。

## 测试

1. 桌面浏览器：展开输入条，逐行输入至超过半屏，确认文本框向上长、盖住终端底部、「发按键 / 换行」贴屏幕底且可见；超半屏后内部滚动。
2. 输入条关闭后，底部栏与快捷键正常显示，无终端文字透出。
3. 窗口缩放/终端大小切换（`大` 按钮）后吸底仍正确。
4. 安卓真机（HTTPS）：展开输入条 + 软键盘弹起，确认输入条在键盘上方、可正常输入与发送。
